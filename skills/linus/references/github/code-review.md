# Revisão de código

Leia o diff completo e os contratos afetados. Procure regressões, falhas de autorização, perda de dados, concorrência e incompatibilidade, além de estilo. Siga o caminho real de execução e confira testes relevantes.

Cada achado precisa de condição de falha, efeito e arquivo/linha na revisão certa. Não invente comentários para preencher uma quota. Preparar a revisão é diferente de publicá-la no GitHub; mensagens/comentários remotos só são enviados quando autorizados. Use gh pr diff, gh pr view e gh api para leitura e operações específicas.
